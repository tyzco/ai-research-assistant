# PaperLink 检索评估基准 — 方法与声明边界

> 目的: 给「能否对外宣传检索数字」一个诚实答案。
> 原则: 报告必须同时给出 指标 + 环境 + 局限, 缺一不可。

## 怎么测

```bash
python run_benchmark.py --kb <表名> [--topk 5]   # 多主题基准 (默认 data/benchmark_qa.json, 30题/5主题)
python run_eval.py --kb <表名>                   # 内部回归 (8题, 防退化用)
```

**指标**:
- `R@topk`: top-k 检索文本与参考答案的**最大语义余弦相似度** (semantic_recall)
- `MRR`: 第一个相似度≥0.75 的排名倒数

## 诚实声明（对外必读）

**能说**：
- 我们搭了**评估 harness**（多主题、分主题统计、环境/局限文档化、回归门禁）
- **相对结论**：4096 块 > 2048 块 (+1.4%)、相关度重排让关键论文浮出、级联重排（MiniLM→bge-reranker）
- 设计事实：12 源、1M 上下文防幻觉、混合检索

**不能说**（会被攻击）：
- 具体数字（如 R@5 0.82）当「我们的性能」—— 样本小/主题少/语义近似非答对
- `MRR 1.0` —— 是测试集太容易，不是强

**指标的性质**：
1. `semantic_recall` 是**语义近似**，不是「答案对不对」。检索到相关但不等于答对。
2. 分数**上界受限于知识库覆盖面**：KB 没有该主题论文 → 分低，反映覆盖率而非检索质量。
3. LLM 判分（faithfulness 等）是 LLM 当判官，有偏差，不能当金标准。
4. 换嵌入模型/网络/判官，绝对值会变；**相对比较比绝对值稳健**。

## 要报可信数字的路径

1. **KB 覆盖主题**：为每个基准主题准备真实论文（下载 OA/用户上传），重建知识库
2. **基准集**：50-100 题 / 10+ 主题，参考答案**人工校验**
3. **指标**：MRR 掉到 0.5-0.8（真实分布）+ 抽样人工判「答对率」
4. **环境**：写明嵌入模型、网络、判官、样本量

## 当前数字的真实含义

`data/benchmark_report.json` 里的数字 = **内部回归参考**，不是对外性能声明。
跑出来的分主题分布（即使 KB 只有 10 行也 0.76-0.80 的「地板」）正是语义近似 + 小样本的信号 —— 这也是为什么不能拿它当基准数字。
