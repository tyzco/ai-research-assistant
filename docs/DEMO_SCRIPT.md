# PaperLink v4.0 演示脚本 (5 分钟面试版)

> 适用于面试视频录制。每步标注时间、画面、操作、讲解词。

---

## Step 1: 启动与首次体验 (0:00-0:40)

**画面**: 终端执行 `docker-compose up -d`，打开浏览器 `localhost:8001`

**操作**:
1. `cp .env.example .env` + 填入 DEEPSEEK_API_KEY
2. `docker-compose up -d`
3. 打开 Chrome → `localhost:8001`

**讲解词**:
> "PaperLink 是一个面向研究者的学术效率工具。它通过 13 个 AI Agent 组成虚拟科研团队，覆盖从选题评估到终稿定稿的完整流程。我们采用 Agent 自动执行 + 人工关键节点审批的双轨机制，确保学术质量。只需要一个 DeepSeek API Key，其他所有模型（嵌入、重排、PDF 解析）全部本地运行。"

---

## Step 2: 输入研究方向，触发多源搜索 (0:40-1:20)

**画面**: 输入 "Transformer 注意力机制的最新进展"，展示 SSE 分批搜索结果

**操作**:
1. 输入框输入研究方向
2. 点发送（不选 Agent 模式，直接用通用模式创建课题）
3. 右侧论文面板实时出现 arXiv → OpenAlex → S2+CNKI 三批结果

**讲解词**:
> "输入研究方向后，系统自动生成中英文检索策略，在 12 个学术数据库中并行搜索。我们用的是 SSE 流式分批返回——arXiv 最快 6 秒就有结果，不阻塞后续批次。右侧面板按 OA 可下载状态标注，可一键下载构建知识库。"

---

## Step 3: 一键建库 + RAG 问答 (1:20-2:00)

**画面**: 点 Download & Build → 进度条 → KB 就绪 → 提问 → 展示带引用的回答

**操作**:
1. 点论文面板 "Download & Build"
2. 进度条显示下载/解析/建库进度
3. KB 就绪后，切到「知识库」模式
4. 提问 "这些论文中哪些方法效果最好？有什么优缺点？"

**讲解词**:
> "一键下载后，PDF 经过 PyMuPDF 解析、LangChain 语义分块、bge-small-zh 向量化，存入 LanceDB。问答时走完整的 RAG 链路：指代消解→查询改写→自适应混合检索→级联重排→父子分块扩展→三层 Prompt 生成。每个回答带论文引用。"

---

## Step 4: 科研团队模式 (2:00-4:00) ★核心亮点

**画面**: 选择「科研团队」模式 → 输入任务 → 13 Agent 依次执行 → 审批闸门出现

**操作**:
1. 顶栏下拉框选「科研团队」
2. 输入 "帮我调研对比学习在 CV 领域的最新进展，写一篇综述"
3. 侧边栏显示 Agent 执行进度（选题评估 → 文献检索 → 质量筛选...）
4. **第一个闸门**: 选题方向确认 → 展示评估报告 → 点「确认通过」
5. Agent 继续执行：检索 → 筛选 → **第二个闸门**: 核心文献入选
6. 点「修改后通过」，输入 "增加 ViT 相关的论文"
7. Agent 重新筛选 → 综述合成 → 章节写作 → 审稿 → **第三个闸门**: 终稿定稿

**讲解词**:
> "这是我们的核心差异化能力——虚拟科研团队。13 个 AI Agent 按科研流程分工协作：上游做选题评估和文献检索，中游做综述合成和章节写作，下游做同行审稿和伦理审查。整个流程中设置了三个审批闸门：选题方向、核心文献、最终结论，必须人工确认后才能继续。这样既利用了 AI 的效率，又保证了学术质量——AI 不替代研究者的判断。"

---

## Step 5: 流水线追踪 + 知识图谱 (4:00-4:45)

**画面**: 点「追踪」按钮 → pipeline.html 展示 6 步实时可视化 → 切换到 kg.html 展示图谱

**操作**:
1. 在任一个 AI 回答下点「追踪」按钮
2. pipeline.html 展示改写→检索→BM25→融合→重排→生成的完整链路
3. 每步显示耗时、中间结果、论文标题
4. 切到 kg.html 展示论文-实体关系力导向图

**讲解词**:
> "我们还为面试演示准备了流水线追踪面板，可以看到每一步的耗时和中间结果。知识图谱用 D3.js 实现，从论文摘要中抽取方法、数据集、指标等实体和关系，帮助研究者快速建立领域认知地图。"

2. 输入 "帮我分析 LLaMA 系列模型的演进"
3. Agent 自动调用 search_papers → agent_ask → 综合报告

**讲解词**:
> "除了科研团队的多 Agent 协作模式，我们也有单 Agent 模式。它基于 Hook 驱动的循环，10 个生命周期干预节点可以插入自定义逻辑——比如步数上限控制、上下文压缩、敏感词检测——保障 Agent 安全可控地执行任务。"


## 故障预案

| 场景 | 处理 |
|---|---|
| DeepSeek API 超时 | 说 "API 偶有波动" + retry 自动恢复 |
| 嵌入模型未下载 | 首次启动自动下载，解释 "首次需下载 ~130MB" |
| 某个搜索源无结果 | 其他源继续返回，说 "这是容错设计" |
| 团队模式审批后无响应 | 刷新页面 + GET /team/status 恢复 |
