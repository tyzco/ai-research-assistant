# PaperLink 未实现项重新审视（GAP_AUDIT）

> 对「没做的东西」做一次诚实分类：**忘了做（该补）** / **替代方案替代了（评估是否更好）** / **故意不做（不适合当前阶段）** / **预留扩展点**。
> 目的：区分"缺陷"与"决策"，避免把该补的当决策、把决策的当缺陷。

---

## 结论速览

| 分类 | 数量 | 该行动 |
|---|---|---|
| 🟥 **忘了做（真缺，该补）** | 5 | 补：查重、影响因子/CCF、单元测试、自动幻觉检测、中文分词 |
| 🟨 **替代方案（评估后多数更优）** | 7 | 保留现状 + 2 个补强（pi_agent 可选 plan 阶段、OCR 低优先）|
| 🟩 **故意不做（不适合当前阶段）** | 7 | 维持决策，文档已声明 |
| 🟦 **预留扩展点** | 5 | 维持预留，需要时再加 |

**最重要的诚实结论**：目前项目"缺"的主要是 **2 个学术核心功能（查重、影响因子/CCF）** 是真缺且该补——其余要么有合理替代，要么是刻意取舍。多数"看起来缺"的（微服务/Redis/消息队列/GraphRAG）属于**小项目不该做**，不是忘了做。

## 表 1：🟥 忘了做（真缺，该补）

| 缺失项 | 现状 | 为什么是真缺 | 必要性 | 建议 |
|---|---|---|---|---|
| **查重 / 降重** | 只有意图关键词（scope_gate 里"查重""降重"），无任何实现 | 学术工具核心功能，C 端写论文最常用；技能/意图都预埋了却不做 = 忘了 | **高** | 加一个 `check_plagiarism` 工具：输入段落 → 与私有 KB / 检索结果做 n-gram 重合度 + 来源标注，返回相似度与出处 |
| **期刊影响因子 / CCF 会议等级** | 完全缺失 | `research_decision` 技能宣称做"影响力分析"（趋势/高引），却没有 IF/CCF 数据支撑 | **中-高** | 内置静态映射表（核心期刊 IF + CCF A/B/C 会议）+ 一个 `lookup_venue_rank` 工具 |
| **单元测试（pytest）** | 只有 `test_e2e.py` / `run_eval.py` / `benchmark.py` | 交付/面试/回归都靠 pytest；当前测试是"验证型"非"防护型" | **中** | 为核心模块补 pytest（tool_registry 注册、gate_query 分类、retriever 排序、quota 记账）|
| **自动幻觉检测** | 靠 key_findings 证据 + draft_quality 6 项人工/规则自检 | 无"生成 vs 证据一致性"的自动校验；面试高频题"如何监控幻觉率"答不出落地 | **中** | 加一个 `check_factual_support` 工具：答案断言 → 检索证据 → LLM 一致性判定，返回支持/矛盾/无据 |
| **中文分词（jieba）提升 BM25** | LanceDB FTS 默认分词，中文是整句切分 → BM25 对中文弱 | 中文检索主要靠向量兜底（双语重排），BM25 中文质量差被掩盖 | **低-中** | 可加 jieba 分词后建 FTS；但双语重排已兜底，非阻塞 |

## 表 2：🟨 替代方案替代了（评估是否更好）

| 领域 | 业界方案 | 本项目的替代 | 评估 | 结论 |
|---|---|---|---|---|
| Agent 框架 | LangChain / LangGraph | 自研 `pi_agent` + `research_team` | **更好**：零依赖、可控、贴合审批流、面试可讲原理非调库 | ✅ 维持 |
| 长任务规划 | Plan-and-Execute | research_team 固定流水线（Workflow 嵌入）替代；pi_agent 纯 ReAct | ⚠️ **部分**：流水线更适合确定性流程；纯 ReAct 长任务（整篇论文）有跑偏风险 | ✅ 维持 + **补强**：pi_agent 可加"可选 plan 阶段"（先把任务拆步骤再执行）|
| 缓存 | Redis | 进程内 dict + 过期 | **更适合单实例**：零运维；代价是重启丢失（可接受）| ✅ 维持 |
| Embedding | 云端 API | 本地 bge（ST + FlagEmbedding 双后端）| **更适合**：零成本、隐私、离线；质量略低但有双语重排兜底 | ✅ 维持 |
| 扫描件 PDF | OCR | 只支持带文本层 PDF | ⚠️ 现代论文大多有文本层；老扫描件缺失 | ✅ 维持 + **低优先**：可加 pytesseract/paddleocr |
| 长期记忆检索 | 向量化记忆 | P2/P3 用 bigram 关键词匹配 + SQLite | ⚠️ 小规模够用；数据积累后（>数百条教训）关键词召回衰减 | ✅ 维持 + **预留**：换向量检索 |
| 图谱 | GraphRAG 兜底检索 | `knowledge_graph.py` 仅可视化 | ⚠️ 引用网络图谱检索有真实价值但成本高；当前引用链工具覆盖主要需求 | ✅ 维持（诚实声明过）|
| Token 缓存 | 项目侧 kv 缓存 | DeepSeek 平台自动前缀缓存 + 项目上下文压缩 | ✅ 平台已自动处理 system prompt 前缀 | ✅ 维持 |
| MCP 协议 | 外部工具生态标准 | Function Calling + `tools_extra/` 插件（fetch_url/dataio 已示范）| ✅ 当前工具全进程内，够用；接生态时再加 | ✅ 维持 + 预留 |

## 表 3：🟩 故意不做（不适合当前阶段）

| 不做项 | 原因 | 何时再做 |
|---|---|---|
| 微服务 / 分布式部署 | 单进程 FastAPI + 单容器零运维，个人工具无拆分收益 | 用户量/功能到需水平扩展时 |
| 消息队列 | 无异步高吞吐需求（下载/建库用 asyncio 线程池够）| 引入后台任务/多实例时 |
| Redis | 单实例进程内缓存足够；不引额外运维 | 分布式/多实例时 |
| GraphRAG 完整实现 | 建图+图存储+图查询成本高，收益在长尾 | 知识库规模大、多跳问题变多时 |
| OAuth 登录 | 用户名密码 + JWT 当前够；C 端引流时降低注册门槛有价值 | 商业化引流阶段（加分项）|
| 专门移动端 | 学术写作是桌面重任务 | 有移动浏览需求时 |
| 邮件/消息推送 | `/subscribe` 已能每日检索，但无推送通道（webhook/email）| 订阅产品化时 |

## 表 4：🟦 预留扩展点（知道、留着、不实现）

| 预留项 | 状态 | 触发条件 |
|---|---|---|

## 行动建议（按价值排序）

1. **现在就补（1-2 个工具，一个 tools_extra 文件的事）**
   - `check_plagiarism`（查重）：KB 相似度 + 来源标注 —— **学术工具核心，忘了做**
   - `lookup_venue_rank`（影响因子/CCF）：静态映射 + 工具 —— **支撑 research_decision 技能的空缺**
2. **低成本补强**
   - pi_agent 可选 plan 阶段（防长任务跑偏）
   - 核心模块 pytest（回归防护）
3. **低优先 / 预留**：OCR、自动幻觉检测、中文分词、向量化记忆 —— 需要时再加
4. **维持决策**：微服务/Redis/消息队列/GraphRAG/OAuth/移动端 —— 现阶段不做是对的
