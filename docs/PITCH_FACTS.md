# PaperLink 宣传数据事实清单

> 目的: 告诉「拿什么说、怎么说不被问倒、什么不能说」。
> 原则: 数字必须带环境与局限; 主打产品结果, 不主打裸指标。

## 一、开场白（产品故事，10 秒版）

> 「我们把『选题 → 初稿』做成一条龙：输入研究方向 → 系统回答『有没有人做过』（研究空白分析）→ 12 源检索建私有知识库 → 基于证据问答 → 辅助写作 → 质量清单验收 → 审稿批注。底层 Agent 自动执行 + 人工关键节点审批，规避幻觉。」

## 二、主打卖点（差异化，别人没有）

| 卖点 | 讲法 |
|---|---|
| **研究空白分析** | 输入选题，基于真实检索回答「有没有人做过」，锚定文献、诚实标注不确定 |
| **初稿质量清单** | 6 项自检（研究问题/空白/结构/引用/诚实性/可续写），不过不交付 |
| **自我进化** | 反思重试 + 用户反馈教训 + 成功经验复用，越用越聪明 |
| **私有知识库** | 用户自供论文，隐私友好，合法（仅 OA + 上传） |
| **1M 上下文** | 防幻觉：窗口内证据全保留 |

## 三、可报的技术数字（带方法，可复核）

| 指标 | 值 | 怎么报 |
|---|---|---|
| 检索 MRR | 0.72 | 「多主题基准 30 题/5 主题/43 篇真实论文，MRR 0.72 —— 方法可查 BENCHMARK.md」 |
| 检索 R@top5 | 0.78 | 同上 |
| 分主题 | 人脸 1.0 / LLM 0.67 / RL 0.50 | 「KB 覆盖差异的诚实反映」|
| 分块 | 4096 > 2048 (+1.4%) | 「同批论文 A/B 验证」|

**报法要点**：数字旁必带「样本量 + 主题数 + 方法文档」，别人无法用「样本太少」攻击你 —— 因为你先说了。

## 四、效率故事（别用 R@，用时间）

R@ 是组件指标，效率卖点是**时间**：
- 人工：检索 → 精读 20 篇 → 写综述 → 出初稿 ≈ **数天**
- 工具：同一流程压缩到 **数小时**（Agent 并行检索 + 自动建库 + 辅助写作）
- 诚实话术：「机械部分（检索/整理/引用/格式）自动化，判断留给人 —— 这才是 Agent 即服务的价值」

> 真实计时数据要等真实使用积累（每个 选题→初稿 的耗时记录）。

## 五、什么不能说（会被攻击）

- ❌「R@5 0.82」当绝对性能（那是 8 题冒烟测试，样本太小）
- ❌「MRR 1.0」（挑易答问题的信号）
- ❌「faithfulness 0.82」当金标准（LLM 判官有偏差）
- ❌「12 源」吹成「覆盖所有学术」（部分源是镜像/免费，覆盖有限）

## 六、面试/演示应对模板

**被问「检索准不准？」**：
「我们在 5 主题/30 题/43 篇真实论文上做了基准，MRR 0.72、R@top5 0.78。这个数字不是虚的 —— 评估脚本和局限声明都在仓库里（BENCHMARK.md），你可以自己跑。它反映的是真实表现，包括 KB 覆盖的差异（比如强化学习主题 0.50，是因为那批论文没直接讲清楚那些概念题）。」

**被问「跟 XX 工具比呢？」**：
「不同基准/指标/语料不能直接比。我报的是我们自己方法可复核的数字；如果你要横向对比，我可以跑同一份测试集。相对的结论（4096 块 > 2048、级联重排优于单层）我们做过 A/B，是稳健的。」
